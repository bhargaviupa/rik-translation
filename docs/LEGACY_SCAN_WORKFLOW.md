## Token-saving workflow (decided Oct 2026; OCR was tried — Tesseract and Google Docs — and rejected for words: read page images directly)
1. **One session per sūkta**; start by reading this file and the last ~40 lines of the output file. Keep replies and progress notes short.
2. **Crop before viewing:** `python3 publish/tools/pageprep/crop_pages.py vol9/scans/Rig_Vol9.pdf FIRST LAST /tmp/out --dpi 150 [--strips N]` trims margins (~⅓ fewer pixels). Zoom only where something is unclear. View each page once, then write immediately; never re-view a page already written.
3. **Read numerals correctly the first time** (no second pass). Digit key (confirmed by the reader): ೧ looks like "∩", ೦ like "○"; **the flat-footed "2"-like glyph = 7, the curled "2"-like glyph = 2**; ೬ has a hook at top-left; ೮ looks like ಲ/ಅ; ೯ like ಕ; ೪ like ಳ; ೫ like ಣ; ೩ like ಇ. My usual confusions: 3/5, 6/7, 2/9, 8/9 — zoom each doubtful digit. Record what is **printed**; if it differs from the standard number say so ("as printed"). Many sūtra numbers are simply not printed in the grammar notes — then give none (never supply from memory). Details: `publish/tools/numeral_pass/METHOD.md`. **Correction (Vol 13 zoom-fix passes, Oct 31 2026): there are three look-alike digits — round open-loop glyph = 2, hooked "ಇ/ಖ"-like glyph = 3 (the one most often misread as 2), flat-footed "ಒ"-like glyph = 7; calibrate against the running header (`ಅ. ೨೩ … ಸೂ. ೧೭೪`) in the same crop. Plain *ma* and *ya* are printed with a hook that looks like the ು sign (ಮುರುತಃ = marutaḥ): never read it as *u*. In Pada lines the small subscript stroke is the compound mark (ऽ). Where no reference number is printed, say so; never supply one. Full notes: `vol13/review/numeral_glyph_notes.md`.**
4. **IAST layer by script:** write Devanagari + English only; run `python3 publish/tools/translit/add_iast.py FILE.md` (adds the italic IAST line after each Devanagari blockquote run; inline `⟦देवा⟧` → `देवा (*devā*)`). `--check` lists lines where an existing IAST layer differs from a mechanical transliteration (not fool-proof: sandhi spacing, `[?]`, accents differ — review its output). The final file must still contain all three layers.
4b. **Accents by script (all new volumes, first pass; user decision Nov 4 2026):** after the IAST step, run `python3 publish/tools/accents/accent_volume.py N --write` (add `--html` if the volume crosses a Maṇḍala boundary). It adds the Vedic accent marks (॑ ॒) to every Saṃhitā block from the accented Maṇḍala HTML in `refs/mandala/` (`rv_mandala1.html` … `rv_mandala10.html`: all ten Maṇḍalas, supplied by the user on Nov 5 2026; see `refs/mandala/README.md`). Run it with no `--write` first for a report. Only accent marks are added, the printed spelling is never changed (the script checks this); run it as part of the first pass (after each sūkta), not as a later back-fill. Unmatched lines go to `volN/review/accent_report.tsv` (`--api` can try them with RIK_API_KEY; do not guess accents by hand). Status (Nov 4 2026): done by this script for Vols 7–11; Vol 1 citations only; Vols 2–6 and 13 accented earlier; Vol 14: Maṇḍala 2 part via `vol14/tools/accents.py`, the rest still to run; see `refs/mandala/README.md` for the licence note (personal study, keep the repo private).
5. **Printed English** of each Ṛk (clean Latin type): `python3 publish/tools/english_ocr/english_block.py vol9/scans/Rig_Vol9.pdf PDFPAGE` gives a Tesseract draft; compare with the page, keep the source's misprints marked [sic].
6. Grammar pages (Vyākaraṇa-prakriyā): short note only ("grammar page, noted briefly"; 2–4 lines naming words and legible sūtras). Batch writes (a whole Ṛk or a 4–6 page run per call). Test a smaller model for first drafts if the user asks.

## Conventions (carried over from Volumes 1–8, unchanged)
- **Sanskrit always in three layers** — Devanagari + IAST + English — on every citation, never two layers or IAST alone. Preserve all Sanskrit (complete or incomplete) and all cross-references; never skip or silently omit a citation.
- **(Vols 1–14) View the actual page image before writing**; never pattern-complete Sanskrit from memory or rhythm, even for familiar verses. The bhāṣya, Saṃhitā and Pada are in Kannada script: convert letter by letter; never complete a garbled word from memory — bracket it `[?]`. A clearer later printing of the same phrase may correct an earlier reading (say so).
- **Take the Kannada source at face value** (no cross-checking against outside sources) except standard reference material (metre names etc.). **Honesty about uncertainty:** `[?]` for doubtful readings/numerals; formatting confidence never exceeds reading confidence; never fabricate.
- Glosses I add to Ṛgveda citations the source leaves untranslated are labelled "mine and tentative". Ṛgveda citations in the Special Topics: three layers + short gloss.
- The source prints its own English translation of each Ṛk (and Western scholars' English): reproduce as printed, misprints marked [sic].
- **Per Ṛk structure:** Saṃhitā-pāṭha, Pada-pāṭha (printed *after* the Saṃhitā — do not note word-division until the Pada is viewed), Sāyaṇa-bhāṣya (with sense; its grammatical tail characterized, not transcribed), Pratipadārtha, Bhāvārtha, printed English, Special Topics (Viśeṣaviṣayagaḷu), Vyākaraṇa-prakriyā (noted briefly). Accent marks on the Saṃhitā are added by script from the reference text (step 4b); the Pada is not accented.
- Check the printed page number on each rendered page against what was just written (scans have duplicated/missing pages — Vol 7 p. 413, Vol 8 p. 323: note gaps in the text). When a Special Topics passage runs across a page break, split it where the print splits it. *Dvaipada* sūktas count Ṛks by printed units. The last sūkta of an adhyāya ends with a Sanskrit colophon and a Kannada closing line (three layers).
- **Progress-note pattern:** one block at the very end of the .md (printed page reached, one-line summary, open flags); each new note replaces the previous. Append helper must strip only the final "**Progress note:**" (assert it lies in the last ~20,000 characters), assert the file did not shrink, and assert exactly one note afterwards. Never `git checkout`/restore the output file mid-session.
- No `.docx`/PDF generation mid-stream; at the end of a sūkta or on request: `pandoc -f markdown-yaml_metadata_block FILE.md -o FILE.docx --toc --toc-depth=2`, then set the Indic font inside the DOCX styles (pandoc's `-V mainfont` does not reach a DOCX): `python3 publish/tools/numeral_pass/docx_csfont.py FILE.docx "Lohit Devanagari"` for English files (**Lohit Devanagari draws the svarita ॑ as a vertical stroke above the syllable**; Noto Serif/Sans Devanagari and Annapurna SIL draw it as a dot or beside the syllable — decided Oct 2026), `"Noto Serif Kannada"` for Kannada files; then `soffice --headless --convert-to pdf FILE.docx`, and check the Devanagari/Kannada counts of the PDF text match the .md and that it has no dotted circles (◌). Fonts are not preinstalled in cloud sessions: `apt-get install fonts-lohit-deva fonts-noto-core`. In accented lines the accent mark goes **after** a visarga/anusvara (`भिः॑`, not `भि॑ः`), otherwise the font prints a dotted circle. Designed print PDF: `python3 publish/build_vol45.py N full` (cleaner `publish/vol67_clean.py`; first-person remarks are rewritten impersonally by `publish/voice.py`: run `voice.residual()` and add new phrases to `voice.EXACT`); review worklist: `python3 publish/review_all.py`.

## Cost-saving rules for Volume 11 onwards (decided Oct 2026)
- **Bhāṣya stays in Sanskrit:** transcribe the Sāyaṇa-bhāṣya in Devanagari (IAST by script) and give **no English rendering of it**, only a one-line gist (≤ 25 words) per Ṛk when the sense is not obvious from the Pratipadārtha. The Kannada file converts it by script as before. Its grammatical tail is still transcribed (it is Sanskrit, cheap) but not explained.
- **Grammar pages:** English note only (2–4 lines naming words); the Kannada file carries the headwords and legible sūtra names, not every numeral. Small-type numerals: `[?]`, no zooming.
- **Printed English of each Ṛk:** start from `english_block.py` output and compare, not retype.
- **Images:** view at ~120 dpi; zoom only a crop that cannot be read.
- **Turn economy (Nov 2026):** every tool call re-reads the whole context, including all images viewed so far. Issue independent calls in parallel (view all strips of a page or batch in one message, zoom in one message), write a page with one call, work in batches of ~3 pages. See `vol14/vol14_runbook.md` "Turn economy".
- **Kannada prose drafts** (Pratipadārtha, Bhāvārtha, Special Topics): may be drafted by a smaller model if the user asks; I review `[?]` lines and the Sanskrit.
- Put italic notes **before** a Devanagari block or after its IAST line (a note right after the block stops `add_iast.py` adding the IAST).

## Lessons for new volumes' set-up (Oct 30, 2026; details in `vol13/vol13_runbook.md`, last section)
Do not run whole-volume Tesseract scans (20+ min; used only to locate). Read printed page numbers from header-strip contact sheets (`vol13/tools/numsheets.py`, header row located by ink profile, not a fixed fraction). Crops are whole-page fractions. Check a prompt's claims (e.g. "pages upside down") by eye before building tools. Confirm range numerals against the contents' word forms. Front matter has its own roman numbering. If `git checkout` fails on an LFS "should have been a pointer" file, use the `GIT_LFS_SKIP_SMUDGE=1 … checkout -f` recipe. Kill background jobs by PID.
