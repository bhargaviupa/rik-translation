# Kannada text from page scans: transcription and repair (for every volume that has no machine-read text)

Made on Vol 25 and Vol 26 part 2 (Nov 24–26 2026). **Read this before reading any scan.** A session that reads scans uses these tools and this order; nothing here calls the API (agents read images with the Read tool). Tools are in `tools/rv/` (`scan_*.py`, `ws_fill.py`); `python3 tools/rv/scan_repair.py` runs them in order (`init`, `status`, `step1`, `crops`, `vote`, `rebuild`; config `volN/scan_config.json`). Prompt templates: `tools/rv/scan_prompts/` (NUM, WORD, PAGE; `crops` copies them to `volN/review/crops_read/`).

## What went wrong the first time (so it is not repeated)
Vol 25: 877 pages read by agents, 6 pages per agent, from half-page images, `[?]` as the only safeguard. Result: 1,451 `[?]` marks (898 words, 358 numbers, 195 head digits), more that were never marked, and normalised spellings (ಎಲ್ಲೈ→ಎಲೈ, ಸೋಮು→ಸೋಮ), invented head digits, `**` markup, one global `sed`. Settling the marks cost about 6 million tokens, several times what careful reading would have cost. Accuracy of the first pass was never measured; the only objective number is the pilot's 83% of word-meaning headwords found in the Wikisource Pada.

## The process (in this order)
1. **Render** (`scan_pilot.py render`): two half-page JPGs per page.
2. **Pilot (12 pages) and measurement** as in the VOL26 prompt; do not go on before the user says yes.
3. **Read in batches of 3 pages** (not 6), one fresh agent per batch, with the prompt of the volume prompt file **and these additions**: copy the print's letters (ಎಲ್ಲೈ stays ಎಲ್ಲೈ, ಸೋಮು stays ಸೋಮು); never infer a head digit; no `**`; no `sed`/global substitution; every look-alike digit (೩/೫, ೬/೭, ೮/೯, ೨/೩/೭) in a reference is looked at twice, and `[?]` goes after any digit or letter not seen clearly (under-marking is the worst error).
4. **After every batch (free):** `scan_check.py` (page heads, other scripts, markers), `scan_wordfix.py` (words against the Wikisource Saṃhitā/Pada/bhāṣya words of the sūkta ±1), headword check against the Pada, Ṛk numbers against the index. A batch that fails is read again at once, while its images are at hand.
5. **After the volume, `scan_repair.py step1`:** Tesseract OCR of every page (`scan_ocr.py`; a second reader, never a corrector; it reads Kannada digits badly), `scan_questions.py` (every `[?]` as a row of `review/questions.tsv`, stable id = page-line-hash), `scan_wordfix.py --apply`, `scan_heads.py --apply` (heads from the unmarked heads before/after them, the two fixed head titles, the page number = PDF − offset), numbers backed by the OCR cleared.
6. **`scan_repair.py crops`:** `scan_crops.py` finds the printed line of each mark (Tesseract word boxes) and cuts an enlarged strip; ten strips per mosaic; a reader per ~6 mosaics (pass A), a second independent reader (pass B). Words: pass WA on every mark, a second pass WB only where WA differed from the first reader or was only `likely`.
7. **`scan_repair.py vote`** (`scan_vote.py`): a value is applied only when two independent readings agree (A=B; or the first reader is backed by A or B; or the OCR backs a reader). Words: the first reader backed by a `certain` reading, or by a `likely` one only if the word occurs ≥2 times elsewhere unmarked. Everything else stays open for the user (`votes_open*.tsv`). Every change is logged (`reread_applied.tsv`, `wordfix_applied.tsv`, `heads_applied.tsv`, `repair_log.md`). A reader that cannot see the place says `unreadable`.
8. **Marks the crops could not find** (damaged print garbles the OCR exactly where the mark is) go to page-level jobs: `scan_reread.py plan VOL --pages 4 --kinds head,number`, prompt PAGE.md. Their answers are applied only where they agree with the first reader or a crop reader; the readers disagreed about the print's digit shapes, so one reading is not enough.
9. **`scan_repair.py rebuild`**, then `ws_fill.py`; the Wikisource colophon of the last Ṛk duplicates the printed one when the print carries it (remove it by hand, log it).
10. What is left goes to the user as a list with crops (or to the user's numeral file, `publish/tools/ref_check/NUMERAL_FILE_LESSONS.md`).

## Rules learned the hard way
- **Do not regenerate `questions.tsv` between cutting the crops and applying the votes** if the ids can change. The ids are stable now, but answer files made before Nov 26 used sequence numbers (`Q0001…`): `scan_reread.py apply` refuses rows whose `expect` column (the reading) does not match, after a stale file once rewrote 108 unrelated places (reverted).
- A reader that finishes in seconds with a full answer file did not look at everything: tell each agent to open every image with the Read tool.
- Agents must see the question's token only as a pointer (the first reader's token can be wrong), and must not see other readers' answers.
- Two readings that agree are strong, not proof (same kind of reader). Digits stay the weak point; use an independent source whenever one exists (index counts, contents page numbers, Ṛk ranges, the user's numeral file).
- A page file edit is always a logged change; Wikisource is never edited.
