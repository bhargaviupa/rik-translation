# Prompt for the Vol 23 session (paste into a new Claude Code session on this repo; Sonnet is enough)

You **translate Volume 23** of the Rigveda translation (repo `bhargaviupa/rik-translation`) from the user's machine-read text by the **Batch API route**, exactly as Vols 17, 18 (and 22) were made. You do not translate yourself and you start no translator agents: windows go to the API as batches; scripts check and commit them. Read `CLAUDE.md`, then `vol22/STATUS.md` (if it exists) and `vol17/STATUS.md` (the first batch-API volume), `docs/LESSONS.md` 41–54, `docs/HANDBOOK.md` §5, and `docs/prompts/VOL22_API_PROMPT.md` (the same job for Vol 22; its set-up, order of work and stop rules apply here with 22 → 23, and its "Decisions of Nov 21–24" section applies unchanged).

## Money and deadline (ask first, in one question)
- Ask the user: what exactly expires and when (spending, submitting, collecting), how much budget is left, and whether **one yes covers every stage of Vol 23 up to a ceiling** (suggest $20). Never print `RIK_API_KEY`.
- Measured costs: Vol 18 $8.89, Vol 11 $10.36 for about 700–850 pages; Vol 17 $20.14 (of which $8.71 retries). **Send no retries** (default); expect about $9–13.
- Batches can take up to 24 h: submit in as few, as large batches as the estimate allows. `plan` is free; `submit` spends: show the estimate and wait for the yes (or the agreed ceiling).

## Input
The supplied text of Vol 23 is **not in the repository** until the user uploads it (Vol 22's uploads came as `## Page N` files from three OCR runs with mislabelled and missing pages; see `vol22/html/rig_22_merged.md` header). On arrival: check the page labels first (duplicates, mislabels such as a run restarting at 10, empty pages, gaps); **refuse to translate across a gap**: list missing pages for the user and translate only the contiguous range, or wait. Scope from the text itself: Vol 22 covers Maṇḍala 7 Sūktas 50–80 (per its preface), so Vol 23 is expected to continue from Maṇḍala 7 Sūkta 81 (and may run into Maṇḍala 8); say so if the text shows otherwise. Check the sūkta sequence in the contents before `plan`.

## Set-up and order of work
As in `VOL22_API_PROMPT.md`, with 23 for 22: branch = the session's (no force-push, no PR, no merge into `main` unless asked); `pip install indic-transliteration rapidfuzz openpyxl anthropic`; `batch.py new 23 …`; `volcfg.json` conventions copied from `vol21/volcfg.json` (note_style NOTE, no_iast_blocks ["bhashya"], grammar sanskrit, layout subheads, window 6, printed_english_label "English translation", `mandalas` as the text shows); STATUS.md from `docs/STATUS_TEMPLATE.md`; pubcfg from `vol21/pubcfg.json`; merge/figures/`html_pages.py` as in `vol21/STATUS.md` ("Source and inputs"); `audit 23` must print `AUDIT PASS`; `api_batch.py plan 23 --windows 40`; commit, push, report what the text looks like **before any `submit`**. Then: preface (`api_front.py 23 …`), body in few stages (`plan` → yes → `submit` → poll `status` about every 60 s → `collect`; on `STOP at …` repair by `batch.py fix`, never change what the print says; retries only with `--retries 1` and tell the user), `audit` + STATUS + commit + push after each stage, look at one complete Ṛk and the sūkta sequence, and at the end `batch.py rkheads 23 --dry-run`, `kn_headings.py 23 --write`, tick Vol 23 in `PUBLICATION_TODO.md`. Stop there; the finishing checklist is a separate job.

## Stop and tell the user when
`audit 23` fails without a visible reason; `collect` stops twice at the same window; a stage costs more than twice its estimate; the scope does not fit the text (sūkta out of sequence, missing page range); the usage limit is near (commit and push first). Report only what finished commands showed; quote `git log -1` for every commit claimed.
