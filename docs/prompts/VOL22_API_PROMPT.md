You do not translate yourself and you start no translator agents: windows go to the API as batches; scripts check and commit them. Read `CLAUDE.md`, then `vol21/STATUS.md` and `vol17/STATUS.md` (the first batch-API volume), `docs/LESSONS.md` 41–54, and `docs/HANDBOOK.md` §5. Use `vol13/CONTINUE_PROMPT_HTML.md` as the model of the loop (it is the same job for another volume).

## Set-up (once)
1. Branch: the one this session was given (never force-push; no pull request; no merge into `main` unless the user says so). `git fetch origin main && git merge origin/main`.
2. `pip install indic-transliteration rapidfuzz openpyxl anthropic`.
3. New volume as in `docs/HANDBOOK.md` §5: `python3 tools/rv/batch.py new 22 --mandala 7 --start-page 1 --source "vol22/html/FILE@1-N"`; then edit `vol22/volcfg.json` to the **same conventions as `vol21/volcfg.json`** (`note_style` NOTE, `no_iast_blocks` ["bhashya"], `grammar` sanskrit, `layout` subheads, `window` 6, `printed_english_label` "English translation", `mandalas` as the text shows, the session's branch in `branch` and `branches`). `vol22/STATUS.md` from `docs/STATUS_TEMPLATE.md`; `vol22/pubcfg.json` from `vol21/pubcfg.json` (title lines, adhyāya line, imprint; mark unknowns as placeholders).
4. Prepare the text as `vol21/STATUS.md` ("Source and inputs") describes: merge the uploaded files losslessly with `tools/rv/merge_md.py` into `vol22/html/rig_22.md`; pictures out with `tools/rv/extract_figures.py 22 vol22/html/rig_22.md --write` (**keep pictures 1 and 2, the title page and the cover, in `vol22/html/figures/`**: the PDF will use them); run `python3 tools/rv/html_pages.py` on the file: page range, **missing page numbers** (list them in `STATUS.md` now), where printed p. 1 begins (insert `<!-- page 1 -->` if the text has no marker), front-matter line numbers in `vol22/html/_layout.json`. Set `source` in `volcfg.json` to the real page range.
5. `python3 tools/rv/batch.py audit 22` must print `AUDIT PASS`; `python3 tools/rv/api_batch.py plan 22 --windows 40` is free and prints the estimate. Update `STATUS.md`, commit, push, and tell the user what the text looks like before any `submit`.

## Order of work
1. **Preface** (it stands before printed p. 1): `python3 tools/rv/api_front.py 22 FIRST LAST preface` (line numbers from `_layout.json`; one request), repair `work/preface/en.md` by hand only as the message says, then `--install`, `audit 22`, commit, push.
2. **The body in as few stages as the estimate allows:** `plan 22 --windows K` → show the estimate → on yes `submit 22` → poll `status 22` about every 60 s (one job, nothing else on the repo meanwhile) until `ended` → `collect 22`. `collect` applies each answer, logs real usage in `vol22/parts/batch_costs.md`, runs the gates and commits window after window in page order; **do not commit, push or switch branches while it runs**. If it prints `STOP at …`: read `WIN/gate_failure.txt`, repair `en.md` or `kn.md` by hand (`batch.py fix`; letters of the supplied text unchanged; never change what the print says to pass a gate), check with `batch.py done 22 WIN --dry-run`, run `collect 22` again (finished windows are skipped). Only if a whole page was left untranslated, re-send that failure on purpose with `collect 22 --retries 1` and tell the user.
3. After each stage: `audit 22`, update `STATUS.md` (page reached, stage cost, windows needing a hand repair, number of `**NOTE**` marks), commit, push, report in a few lines. **Look at the text itself:** print one complete Ṛk of the new pages and check that no sūkta heading is missing in sequence.
4. **After the last page** (free, by script): `python3 tools/rv/batch.py rkheads 22 --dry-run` says "nothing to change"; `python3 tools/rv/kn_headings.py 22 --write`; update `STATUS.md` with the totals; tick Vol 22 in `PUBLICATION_TODO.md` with the date. Stop there: the finishing checklist (accent report, QA, PDFs) is a separate job.
