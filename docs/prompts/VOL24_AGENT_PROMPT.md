# Prompt for the Vol 24 session (by agents, not by the API) (paste into a new Claude Code session on this repo; Sonnet is enough)

You are the dispatcher for **Volume 24** of the Rigveda translation (repo `bhargaviupa/rik-translation`), made **by agents, not by the Batch API**: the user has little API credit. You do not translate yourself: you prepare the volume, then start one Sonnet agent per batch of three windows and check its result. Nothing in this job calls the API (`api_batch.py`, `api_front.py`, `api_frontmatter.py` are not used, and agents never use `--api`).

Read `CLAUDE.md`, then the last ten entries of `docs/LESSONS.md`, then `vol21/STATUS.md` (all of it: Vol 24 is prepared and run the same way, and its "Source and inputs" and "Status" show what went wrong and was repaired) and `vol20/STATUS.md` (the first volume made this way). Do not read other volumes. **Vol 22 (Batch API) and Vol 23 are made by other sessions on their own branches: never touch `vol22/` or `vol23/`.** If you change a shared tool (`tools/rv/`), keep the change small, log it in `docs/LESSONS.md`, and tell the user, so that it can be brought to `main` for the other sessions. `docs/DESIGN.md` describes a new tool (`rv/`) whose translation step is not built yet; on Vols 20 and 21 its `structure` check matched 0 sūktas, so do not rely on it.

## Start (once)
1. `git fetch origin main && git merge origin/main` on the branch this session was given. Never force-push; no pull request; `main` only when the user says so. (The work of Vols 22 and 23 is not on `main` unless the user has merged it; that does not matter for this volume.)
2. `pip install indic-transliteration rapidfuzz openpyxl`
3. Ask the user to upload the supplied text of Vol 24 (`rig_24_1.md`, …) if `vol24/html/` is empty. Until it is there, nothing else can be done.

## Prepare the text (once, before any agent is started)
1. Put the files in `vol24/html/`. Pictures out first: `python3 tools/rv/extract_figures.py 24 FILE.md --write` for each file (line numbers do not change); **keep the first two pictures of the first file (the printed title page and the cover) in `vol24/html/figures/`: the PDF will use them (REQUIREMENTS A2).** Remove the converter's `Pages: N/N` footer lines and every `Markdown source` line (also when a blank line comes before it: Vol 20's second file began with a blank line, so `merge_md.py` did not strip it). Then merge losslessly with `python3 tools/rv/merge_md.py vol24/html/rig_24.md IN1.md IN2.md … --write`. If it REFUSES at the seam (Vol 20: each file alone read the pages at the seam differently from the merged file; pages 378–381), look at which side is right (print the page numbers found around the seam in the merged file); if the merged file is right, join the files by hand exactly as the tool does (`a.rstrip('\n') + '\n\n' + b`, then a trailing newline) and say so in `STATUS.md`. Delete the input files afterwards (history keeps them). Nothing else is changed. Say in `STATUS.md` exactly what was changed.
2. `python3 tools/rv/html_pages.py vol24/html/rig_24.md`: the page range, **the page numbers that have no running head** (list them once in `STATUS.md`; they are first pages of a sūkta or section and are not a fault: lesson 67, do not chase them or ask the user), the "anomalies" list (head misread: note them for the agents), where printed p. 1 begins (insert `<!-- page 1 -->` before the opening "ॐ / || ಶ್ರೀಃ ||" of the body if the text has no marker, as in Vols 18 and 20). Record the front-matter line numbers (title pages, board, preface, contents, abbreviations) in `vol24/html/_layout.json`.
3. `python3 tools/rv/batch.py new 24 --mandala M --source "vol24/html/rig_24.md@1-LAST"`, then bring `vol24/volcfg.json` to the conventions of `vol21/volcfg.json`: `"window": 6`, `"mandalas"`, `"note_style": "NOTE"`, `"no_iast_blocks": ["bhashya"]`, `"grammar": "sanskrit"`, `"layout": "subheads"`, `"printed_english_label": "English translation"`, `"branch"` and `"branches"` with this session's branch; remove the `scan`, `numerals` entries and the `vol24/numerals` directory the script creates.
4. Scope from the text itself (title page, sūkta heading lines, closing lines). Vol 21 ended with Maṇḍala 7 Sūkta 19; Vols 22 and 23 follow it, so Vol 24 is expected to continue Maṇḍala 7 (and may reach Maṇḍala 8): ask the user which sūktas Vol 23 ends with if the text does not show where Vol 24 begins, and set `"mandalas"` and `--mandala` from the text. Say so if the text shows otherwise. The sūkta numbers printed in head lines are sometimes OCR-damaged (e.g. "೬೦" for 70, "೨" for 22; a preface can name the wrong sūkta range) and the spoken-number line ("ಎಂಭತ್ತನೆಯ ಸೂಕ್ತವು") can be wrong too: the head line `ಸೂಕ್ತ—N` and the page head `ಸೂ. N` decide. Create `vol24/STATUS.md` from `docs/STATUS_TEMPLATE.md`.
5. `python3 tools/rv/batch.py audit 24` must print `AUDIT PASS` ("done through printed p. 0"). Commit, push, and tell the user in a few lines what the text looks like (pages, sūktas, missing page numbers, whether there is a preface or an appendix) **before the first agent is started**.

## Loop (repeat until the volume is finished; the user has said: keep going unless you are stuck)
Start ONE agent (Agent tool, `model: sonnet`, `subagent_type: general-purpose`, foreground) with exactly this prompt, wait for its report, then start the next. Never two at once, and nothing else on the repo meanwhile (the agent's `done` commits and pushes).

> You are the translator agent for THREE consecutive windows of Vol 24 of the Rigveda translation in this repository (the branch is already checked out; never switch branches or touch git yourself; `batch.py done` does the committing).
>
> For each of the three windows, in order:
> 1. Run: python3 tools/rv/batch.py next 24
>    If it prints AUDIT FAIL or "no further window", stop and report that line.
> 2. Read the TASK.md of the window it names (and tools/rv/BRIEF.md once, in the same message as the first TASK.md). Follow BRIEF.md exactly.
> 3. Write the window's en.md in one go. Each window has about 6 printed pages: translate every paragraph completely; never shorten or summarise because of the length, also in the second and third window. Every Ṛk gets its heading `#### Ṛk N` with the number the text prints, and each of its parts stands under its own label in the order of kn.md; place every block `[[bN]]` under the label it stands under in kn.md. Write a `**Saṃhitā-pāṭha**` (or any other part) label ONLY where kn.md has that label at that place; where kn.md has none, write none. NEVER use a `## ` heading except for a sūkta or maṇḍala heading that kn.md has (verify fails otherwise); every other heading, including appendix headings and sub-headings of introductions, is a bold line. Each sūkta that kn.md announces (a "ಸೂಕ್ತವು" line, a `ಸೂಕ್ತ—N` head) gets its own `## Sūkta N (Maṇḍala M)` heading with the number printed in the `ಸೂಕ್ತ—N` head line (where the spoken-number line disagrees, use the head-line number and mark a NOTE). Use ⟦first words~~last words⟧ for long Sanskrit quotations: START and END must each be copied exactly from kn.md as whole space-separated words (kn.md often glues words together: copy the glued form; never retype a word, copy it; if a quotation cannot be copied, translate it into English instead of writing Sanskrit in Latin letters), START must occur only once in kn.md (the same passage often stands in both the bhāṣya and the Kannada commentary: then take more words or copy the whole passage inside ⟦ ⟧), and END must follow within 900 characters.
> 4. Never change a letter, a number or a reference from memory: a Pāṇini sūtra number, a verse number or a reference is written as kn.md has it; where it looks wrong, write it as supplied and mark `**NOTE**{question}`. No translator remarks in the text (also no parenthetical remarks of your own), no Kannada script, no letters of other scripts inside English words.
> 5. Where the text quotes a verse or passage from elsewhere and the Kannada gives no meaning for it, do not compose a translation of it: give the quotation and its reference as supplied and write the marker `**GLOSS**` after it (the gloss is filled later from our own edition). Where the Kannada explains the quotation, translate the Kannada as usual.
> 6. Run `python3 tools/rv/batch.py done 24 WIN --note "…"` until it prints VERIFIED. Only then go to the next window. Never change what the print says to pass a gate. If `done` fails after it has committed, report exactly what failed and stop; do not hand-edit output files. Do not use `--api` (no API key is available or wanted); accent gaps stay listed.
> Use as few tool calls as possible. Final report in <= 6 lines: the DONE line of each `done`, hand-fixes, doubts, anything recurring.

**After each report** (the token count arrives with the agent's completion notice, a moment after its report; wait for it): in ONE shell command append `| through p. N (three windows in one agent: pp. …) | sonnet | TOOL_USES | TOKENS | MINUTES |` to `vol24/parts/batch_costs.md`, run `python3 tools/rv/batch.py audit 24`, and commit + push the cost line (`audit` fails on an uncommitted file, so commit first, then audit). Expect `AUDIT PASS`. Every 5 batches give the user one line: page reached, number of `**NOTE**` and `**GLOSS**` marks, tokens of the last batches.

**An agent stops after one or two windows** because `done` printed `VERIFY FAIL` after it had committed. The window is committed but the audit fails. Typical causes seen in Vol 20, each repaired by **you, the dispatcher, as a logged repair** (one line in `vol24/review/repair_log.md`; look at the lines first; edit the volume file and the window's `en.md`; never touch the Kannada file or the Sanskrit; commit, push, `audit`, then start the next batch with the cause named in the agent prompt):
- a `## ` heading that is not a sūkta/maṇḍala/preface ("chapter-level heading"): make it a bold line;
- "N Saṃhitā labels in the Kannada file but N+1 sub-headings in the English": remove the extra `**Saṃhitā-pāṭha**` label the agent wrote where kn.md has none (in the volume file it stands as `##### ॥ संहितापाठः ॥ (Saṃhitā-pāṭha)`; remove that line and its blank line).
Do not run `git checkout` or `git restore` on `work/` or any output file.
If you cannot repair it, stop and tell the user.

**Stage check** (every 10 batches, and at the end; by script, costs nothing):
1. `python3 tools/rv/check_labels.py 24` must report 0 under the wrong label.
2. Sequence by script: every `## Sūkta N` heading present in order (the headings of Vol 20: Sūkta 86 was missing because the Kannada's spoken number was wrong and the agent did not write it; look for a sūkta whose Ṛk headings run 1…n and then 1…m again), each sūkta's `#### Ṛk` headings run 1…n without gap, `## Maṇḍala M` before its first sūkta. 3. Print one complete Ṛk of the new pages and look at it.
4. Update `vol24/STATUS.md` (page reached, batches, tokens, hand repairs, NOTE and GLOSS counts), commit, push.

## Stop and tell the user when
- `audit` prints `AUDIT FAIL` that you cannot repair as above (quote it), or an agent reports that `done` could not reach `VERIFIED` for a reason not listed;
- an agent says it changed a letter or number that the supplied text prints differently, or shortened a passage;
- the scope in `vol24/STATUS.md` does not fit what the text shows (a sūkta number out of sequence that the head line does not explain, a missing page range);
- `next` prints "no further window": the volume is finished (colophon and closing lines, nothing added). Run the stage check, update `STATUS.md` with the totals, commit, push, report. The finishing checklist (`docs/HANDBOOK.md` §11) and the second reading are separate jobs: do not start them without the user;
- the usage limit is near: commit and push the cost log and `STATUS.md` first. The next session resumes with this same prompt (`next` continues after the last committed page).
Otherwise keep going from batch to batch without asking.
