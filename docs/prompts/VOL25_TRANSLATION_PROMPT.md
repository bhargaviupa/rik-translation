# Prompt for the Vol 25 translation session (paste into a new Claude Code session on this repo; Sonnet is enough)

You are the dispatcher for the **English translation of Volume 25** of the Rigveda translation (repo `bhargaviupa/rik-translation`), made **by agents, not by the API** (no money is spent). **This volume differs from every other one:** no machine-read text of it exists. Another session is making the Kannada text from the page scans, **page by page, on its own branch `claude/wonderful-bardeen-h655ql`** (Phase 1 of `docs/prompts/VOL25_SCAN_AGENT_PROMPT.md`), skipping the Saṃhitā, Pada and Sāyaṇa-bhāṣya blocks; those three layers come from the Wikisource index. Your job is to turn what that session has transcribed into the pipeline's input, fill the skipped blocks, and translate it with the usual agent loop, **while it keeps transcribing**. You never touch its branch or its files.

Read `CLAUDE.md`, the last ten entries of `docs/LESSONS.md`, `docs/prompts/VOL24_AGENT_PROMPT.md` (the translation loop: you follow it, with the changes below), `vol21/STATUS.md`, and the end of `docs/prompts/VOL26_SCAN_AGENT_PROMPT.md` on that branch ("Lessons from the Vol 25 run": `git show origin/claude/wonderful-bardeen-h655ql:docs/prompts/VOL26_SCAN_AGENT_PROMPT.md`). **Never touch `vol22/`, `vol23/`, `vol24/` or `vol26/`.**

## What is known about Vol 25 (Nov 24 2026)
- **Scope:** Maṇḍala 8 from **Sūkta 68** (opening page: "ಅಥ ಷಷ್ಠಾಷ್ಟಕೇ ಪಂಚಮೋಽಧ್ಯಾಯಃ", Aṣṭaka 6 Adhyāya 5, Maṇḍala 8 Anuvāka 7); the contents page (PDF 1–12 are front matter) decides where it ends: ask the user. **PDF page 13 is printed p. 1: printed = PDF − 12.**
- **Done so far in the other session:** PDF pages 13–54 (printed 1–42) and a 12-page pilot, PDF 322–333, as `vol25/work/scan_pages/pNNNN.md` on its branch. Its pilot: running heads in sequence, 0 letters of other scripts, 1–3 `[?]` per page almost all in the running head, 83% of the word-meaning headwords found in the Wikisource Pada (a floor), about 18.7k agent tokens per page. A repair log (`vol25/review/repair_log.md` there) names one defect: an agent copied spellings and the head `ಸೂ. ೬೯` from the neighbouring page by analogy instead of reading the glyphs (pp. 37–42); those words and heads are to be looked at again at the second pass.
- **The transcriptions are not the supplied-text layout.** They have plain label lines (`॥ ಸಂಹಿತಾಪಾಠಃ ॥`, `॥ ಪ್ರತಿಪದಾರ್ಥ ॥`, `English Translation`) and `[[block: samhita|pada|bhashya]]` placeholders; the supplied files (see `vol21/html/rig_21.md`) have markdown `##` label lines and the Sanskrit blocks in Kannada script. The pipeline (`html_to_kn.py`, `html_pages.py`) reads the supplied layout.
- **Ṛk numbers stand inside the skipped blocks**, so they are not in the transcription. A page that begins inside a block carries only the marker line; consecutive markers of one kind across a page break are one block.
- **Cost:** transcription alone is about 18.7k tokens per page (a volume of about 640 pages would be about 12 million tokens) and translation about 10k per page more. Say this to the user in your first report; they decide how much to run and when.

## Make the pipeline's input (a shared tool; no per-volume tools)
1. **`tools/rv/ws_fill.py`** does two things: (a) **assembles** the transcribed pages into `vol25/html/rig_25.md` in the supplied-text layout (look at `vol21/html/rig_21.md`: running head first on each page, labels as `##` lines, `<!-- page 1 -->` before the opening of the body, merged blocks across page breaks); (b) **fills each `[[block: …]]`** with the block in Kannada script from the Wikisource index (`publish/tools/translit/deva_to_kannada.py`; the Saṃhitā from `rik.samhita`, the Pada from `rik.pada`, the bhāṣya from the Ṛk's paragraphs `para` M.S.R.P). **How it finds the Ṛk:** the k-th `samhita` marker of a sūkta is Ṛk k; the bhāṣya marker before the first Ṛk is the sūkta introduction (R = 0); a later bhāṣya marker belongs to the Ṛk the page prints it under, and the commentary of two or three Ṛks stands with the last of them (`rik.bh_at`). **Checks it prints, and you must show the user:** per sūkta, `samhita` markers = the index's Ṛk count; `pada` markers = the same; bhāṣya markers = 1 + the number of distinct `bh_at` Ṛks; no block missing, none twice (REQUIREMENTS D17). A sūkta whose counts do not agree is listed and **not filled**; the Wikisource text is never edited or compared, its three known defects (5.5.11, 9.97 Ṛk 10, 10.27 Ṛk 1) get a `NOTE`. First look in `origin/main` and on the other branch for `tools/rv/ws_fill.py`: if it exists, use it; if not, write it and **tell the user at once** so that the other session does not write a second one.
2. Show the user **one filled Ṛk** and the count table before running it on the pages.
3. Pictures: pictures 1 and 2 of the volume are the title page and the cover (PDF pages in the front matter); the other session or the user supplies them; do not search for them.
