# Prompt for the Vol 29 session (by agents, not by the API) (paste into a new Claude Code session on this repo; Sonnet is enough)

You are the dispatcher for **Volume 29** of the Rigveda translation (repo `bhargaviupa/rik-translation`), made **by agents, not by the Batch API**, exactly as Vol 24 was made (Nov 24–25 2026: 127 windows in 42 batches, about 7.2M agent tokens, about 9k tokens a page, no API money). You do not translate yourself: you prepare the volume, then start one Sonnet agent per batch of three windows and check its result. Nothing in this job calls the API (`api_batch.py`, `api_front.py`, `api_frontmatter.py` are not used, and agents never use `--api`).

Read `CLAUDE.md`, then the **"Vol 24 lessons"** section and the last ten other entries of `docs/LESSONS.md`, then `vol24/STATUS.md` (all of it: it is the model run, and its "Source and inputs", "Status" and "Open items" show what went wrong and was repaired) and `vol24/review/repair_log.md` (every kind of repair the dispatcher made). Do not read other volumes. **Other sessions work on other volumes on their own branches (Vols 25–28 and later): never touch any `volN/` except `vol29/`.** If you change a shared tool (`tools/rv/`), keep the change small, log it in `docs/LESSONS.md`, and tell the user, so that it can be brought to `main` for the other sessions.

## Start (once)
1. `git fetch origin main && git merge origin/main` on the branch this session was given. Never force-push; no pull request; `main` only when the user says so.
2. `pip install indic-transliteration rapidfuzz openpyxl`
3. Ask the user to upload the supplied text of Vol 29 (`rig_29_1.md`, …) if `vol29/html/` is empty. Until it is there, nothing else can be done. Ask at the same time which maṇḍala and sūkta range Vol 29 holds, if the text does not show it at once (Vol 24 ended inside Maṇḍala 8; the volumes after it continue there and in the later maṇḍalas).

## Prepare the text (once, before any agent is started)
1. Put the files in `vol29/html/`. Pictures out first: `python3 tools/rv/extract_figures.py 29 FILE.md --write` for each file (line numbers do not change); if the first file's first two pictures are the printed title page and the cover, keep them in `vol29/html/figures/` (the PDF will use them; in Vol 24 the text had none). Remove the converter's `Pages: N/N` footer lines and every `Markdown source` line (also when a blank line comes before it). Then merge losslessly with `python3 tools/rv/merge_md.py vol29/html/rig_29.md IN1.md IN2.md … --write`. **If it REFUSES at the seam** (Vol 20 and Vol 24 both: each file alone reads the pages at the seam differently from the merged file), look at which side is right (print the page numbers found around the seam in the merged file); if the merged file is right, join the files by hand as the tool does (`a.rstrip('\n') + '\n\n' + b`, then a trailing newline) **and make sure a `---` page separator stands between the last page of the first file and the first page of the second** (in Vol 24 it did not: the seam page was merged with its neighbour in the page chunks, and the later page numbers were off by one in every check that counts `---`). Delete the input files afterwards (history keeps them). Say in `STATUS.md` exactly what was changed.
2. `python3 tools/rv/html_pages.py vol29/html/rig_29.md`: the page range, the page numbers it did not find, the "anomalies" list. **The supplied text has a `---` line after every printed page: from the `<!-- page 1 -->` marker on, chunk k (k = 1, 2, …) is printed page k. Use this to understand the list of missing numbers**: a number is missing when the splitter did not read the running head (a first page of a sūkta that prints none, but also heads with OCR slips such as `ಸಾಯಣಭಾವ್ಯಸಹಿತಾ`, `ಋಗ್ವೇದಸಹಿತಾ`, a number read as another). Where printed p. 1 begins: insert `<!-- page 1 -->` before the opening "ॐ / || ಶ್ರೀಃ ||" of the body if the text has no marker. Record the front-matter line numbers (title pages, board, preface, contents, abbreviations) in `vol29/html/_layout.json`.
3. `python3 tools/rv/batch.py new 29 --mandala M --source "vol29/html/rig_29.md@1-LASTPRINTEDPAGE"` (**the range is printed pages, not lines**; `new` writes the number of lines: correct it), then bring `vol29/volcfg.json` to the conventions of `vol24/volcfg.json`: `"window": 6`, `"mandalas"`, `"note_style": "NOTE"`, `"no_iast_blocks": ["bhashya"]`, `"grammar": "sanskrit"`, `"layout": "subheads"`, `"printed_english_label": "English translation"`, `"branch"` and `"branches"` with this session's branch; remove the `scan`, `numerals` entries and the `vol29/numerals` directory the script creates. Create `vol29/parts/` and `vol29/review/`.
4. Scope from the text itself (title page, sūkta heading lines, closing lines, the contents list and the preface). The sūkta numbers printed in head lines are often OCR-damaged (in Vol 24: `ಸೂಕ್ತ-೨೨` for 32, ೨೫ for 35, ೨೯ for 39 …) and the spoken-number line can be wrong too: the particulars line `ಸೂಕ್ತ—N` and the announcement decide; the damaged head is a NOTE. Create `vol29/STATUS.md` from `docs/STATUS_TEMPLATE.md`.
5. `python3 tools/rv/batch.py audit 29` must print `AUDIT PASS` ("done through printed p. 0"). Commit, push, and tell the user in a few lines what the text looks like (pages, sūktas, missing page numbers, whether there is a preface or an appendix, pictures) **before the first agent is started**.

## Loop (repeat until the volume is finished; the user has said: keep going unless you are stuck)
Start ONE agent (Agent tool, `model: sonnet`, `subagent_type: general-purpose`, foreground) with exactly this prompt, wait for its report, then start the next. Never two at once, and nothing else on the repo meanwhile (the agent's `done` commits and pushes; accent-report files showing as modified while an agent runs are its own: do not commit them).

> You are the translator agent for THREE consecutive windows of Vol 29 of the Rigveda translation in this repository (the branch is already checked out; never switch branches or touch git yourself; `batch.py done` does the committing).
>
> For each of the three windows, in order:
> 1. Run: python3 tools/rv/batch.py next 29
>    If it prints AUDIT FAIL, stop and report that line. If it prints "no further window", stop: the volume is finished; report that.
> 2. Read the TASK.md of the window it names (and tools/rv/BRIEF.md once, in the same message as the first TASK.md). Follow BRIEF.md exactly.
> 3. Write the window's en.md in one go. Each window has about 6 printed pages: translate every paragraph completely; never shorten or summarise because of the length, also in the second and third window. Every Ṛk gets its heading `#### Ṛk N` with the number the text prints, and each of its parts stands under its own label in the order of kn.md; place every block `[[bN]]` under the label it stands under in kn.md. Write a `**Saṃhitā-pāṭha**` (or any other part) label ONLY where kn.md has that label at that place; where kn.md has none, write none. NEVER use a `## ` heading except for a sūkta or maṇḍala heading that kn.md has (verify fails otherwise); every other heading, including appendix headings and sub-headings of introductions, is a bold line. Each sūkta that kn.md announces (a "ಸೂಕ್ತವು" line, a `ಸೂಕ್ತ—N` head, the line `ಮಂಡಲ—M ॥ ಅನುವಾಕ—A ॥ ಸೂಕ್ತ—N ॥`) gets its own `## Sūkta N (Maṇḍala M)` heading, placed before that sūkta's Sāyaṇa-bhāṣya block, with the number printed in the `ಸೂಕ್ತ—N` head line; where the head line is damaged (e.g. `ಸೂಕ್ತ-೨೨` for 32) or disagrees with the spoken-number line or the particulars line, still WRITE the heading, using the number that the particulars line and the announcement agree on, and mark a NOTE. NEVER leave a sūkta without its `## Sūkta N` heading (in Vol 24 one was left out because of a damaged head line and nothing noticed it). Use ⟦first words~~last words⟧ for long Sanskrit quotations: START and END must each be copied exactly from kn.md as whole space-separated words (kn.md often glues words together: copy the glued form; never retype a word, copy it; if a quotation cannot be copied, translate it into English instead of writing Sanskrit in Latin letters), START must occur only once in kn.md (the same passage often stands in both the bhāṣya and the Kannada commentary, and a start that also occurs earlier makes the quotation run on for thousands of characters: then take more words or copy the whole passage inside ⟦ ⟧), and END must follow within 900 characters.
> 4. Never change a letter, a number or a reference from memory: a Pāṇini sūtra number, a verse number or a reference is written as kn.md has it; where it looks wrong, write it as supplied and mark `**NOTE**{question}`. A seer's or deity's name in the particulars line is written as the particulars line prints it (transliterated letter for letter), with a NOTE if it differs from the name used elsewhere; never substitute the name you know. A NOTE stands alone as `**NOTE**{question}`: never add a sentence of your own about what the print shows (no "is printed with the number …" remarks in the prose). No translator remarks in the text (also no parenthetical remarks of your own, no "as the preceding window left it"), no Kannada script, no letters of other scripts inside English words.
> 5. Where the text quotes a verse or passage from elsewhere and the Kannada gives no meaning for it, do not compose a translation of it: give the quotation and its reference as supplied and write the marker `**GLOSS**` after it (the gloss is filled later from our own edition). Where the Kannada explains the quotation, translate the Kannada as usual. Every printed-English paragraph ("English Translation.") of the Kannada is translated or copied: none is left out.
> 6. Run `python3 tools/rv/batch.py done 29 WIN --note "…"` until it prints VERIFIED. Only then go to the next window. Never change what the print says to pass a gate. If `done` fails after it has committed, report exactly what failed and stop; do not hand-edit output files. Do not use `--api` (no API key is available or wanted); accent gaps stay listed. Repair kn.md ONLY with `python3 tools/rv/batch.py fix 29 WIN …` (never with your own script: it is not logged); a failed `done` can regenerate kn.md and wipe earlier `fix` repairs, so after a failed run check that your repairs are still in place and apply them again if not. A page whose running head was missed (the script warns that a page is much longer than usual) gets its marker by `batch.py fix`.
> Use as few tool calls as possible. Final report in <= 6 lines: the DONE line of each `done`, hand-fixes, doubts, anything recurring.

**After each report** (the token count arrives with the agent's completion notice, a moment after its report; wait for it): in ONE shell command append `| N | through p. P (three windows in one agent: pp. …) | sonnet | TOOL_USES | TOKENS | MINUTES |` to `vol29/parts/batch_costs.md` (header row once: `| batch | printed pages | model | tool uses | tokens | minutes |`), run `python3 tools/rv/batch.py audit 29`, and commit + push the cost line (`audit` fails on an uncommitted file, so commit first, then audit). Expect `AUDIT PASS`. Every 5 batches give the user one line: page reached, number of `**NOTE**` and `**GLOSS**` marks (count with `grep -o`, not `grep -c`), tokens of the last batches.

**An agent stops after one or two windows** because `done` printed `VERIFY FAIL` after it had committed. The window is committed but the audit fails. Each is repaired by **you, the dispatcher, as a logged repair** (one line in `vol29/review/repair_log.md`; look at the lines first; edit the volume file and the window's `en.md`; never touch the Kannada file or the Sanskrit; commit, push, `audit`, then start the next batch with the cause named in the agent prompt):

- "N Saṃhitā labels in the Kannada file but N+1 sub-headings in the English": remove the extra `**Saṃhitā-pāṭha**` label the agent wrote where kn.md has none (in the volume file it stands as `##### ॥ संहितापाठः ॥ (Saṃhitā-pāṭha)`);

Do not run `git checkout` or `git restore` on `work/` or any output file. If you cannot repair it, stop and tell the user.
**The usage limit stops an agent in the middle of a batch** (Vol 24, batch 21): after the reset, `SendMessage` to the same agent id ("continue where you stopped; run `next`") resumes it without loss; its token figure then counts only the resumed part: say so in the cost line.

**Stage check** (every 10 batches, and at the end; by script, costs nothing):

- `next` prints "no further window": the volume is finished (colophon and closing lines, nothing added). Run the stage check, update `STATUS.md` with the totals, commit, push, report. Then continue with "Finishing" below **only if the user has asked for it**;
- the usage limit is near: commit and push the cost log and `STATUS.md` first. The next session resumes with this same prompt (`next` continues after the last committed page).
Otherwise keep going from batch to batch without asking.
