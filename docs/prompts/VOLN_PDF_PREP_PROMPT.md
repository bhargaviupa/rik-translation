# Prompt: prepare the English review PDF of one volume (any of Volumes 1–30; replace N)

You prepare the **English review PDF of Volume N** of the Rigveda translation (repo `bhargaviupa/rik-translation`). The model is Volume 1 (English book), prepared on Nov 25–27 2026: generic remarks out of the text, then builds with the shared print rules, a check, the user's review. **The Kannada book is not part of this task. Nothing is translated, no Sanskrit is corrected, one volume only.**

The prompt is the same for every volume. **What differs between volumes is read from a script, never from this prompt** (a table typed here is out of date as soon as another session merges). If this prompt and the script disagree, the script is right.

## Read first (in this order, and only these)
1. `CLAUDE.md`.
2. `docs/REQUIREMENTS.md`: **A2a** (order of the pages), **A4 "Print rules"** (rules 1–17 and the paragraph "How a comment of the user on a PDF is handled"), **B4.6**, **B2.6–B2.7**, **D22**.
3. `docs/HANDBOOK.md` §8, the paragraph "Rules of every PDF build".
4. `docs/LESSONS.md`: the section "PDF builds of all volumes" and the entries of Nov 26 2026 after it.
5. `vol1/review/repair_log.md` from the entry of 2026-11-25 on, and `volN/STATUS.md`.

## Step 0. The facts of this volume (before anything else)
`git fetch origin main && git merge origin/main` on the branch you were given; install: `pip install weasyprint pypandoc indic-transliteration rapidfuzz openpyxl lxml` and `apt-get install -y fonts-lohit-deva fonts-noto-core fonts-lohit-knda`. Then **`python3 publish/pdf_prep_report.py N`** (details and the headings before the text) and, for the state of all volumes, `python3 publish/pdf_prep_report.py`. It tells you: the **family**, the builder, the page-heading layout, counts of `[?]`, `[sic]`, `**NOTE**`, `**GLOSS**`, Kannada-script lines, lines ending in dots, the dry-run count of the clean-up, whether the English file holds a preface, a contents section, an introduction, whether `contents_en.json`/`frontmatter_en.json` exist, whether the volume was prepared already, and a verdict.
- **Stop and tell the user** if the English file is missing, the translation is unfinished, or the verdict says the completeness is unclear (then read `volN/STATUS.md` and ask). A volume that is "prepared already" is only re-built and checked.
- **The families** (what changes in the procedure; everything else is the same):
  - **A, Vols 1–10:** made from scans, old builders (`build_vol1.py`, `build_vol2.py`, `build.py`, `build_vol45.py`, each with its own cleaner `publish/vol*_clean.py`). Text full of remarks, `[?]`, `[sic]`, `**GLOSS**`. The preface and contents, **if present at all**, are sections of the English file.
  - **B, Vols 12, 14, 15, 16:** older text with remarks and many Kannada words in them; built by `volbook.py`; mostly no `pubcfg.json`. Preface and contents come from `frontmatter_en.json` / `contents_en.json` where those exist (Vol 15 only), not from the English file.
  - **C, Vols 11, 13, 17–30:** NOTE style: the text is clean at the source (the clean-up finds a few lines), `**NOTE**` and `**GLOSS**` are the editor's markers: they **stay and print in a review copy** and are counted in the hand-over, never removed. `volbook.py`. The preface is a section of the English file; the contents come from `contents_en.json` where it exists (Vols 15, 18, 21), otherwise there are none.

## Steps, in this order
**Step 1. Baseline.** If the volume has no `volN/pubcfg.json`, write a minimal one on the pattern of `vol17/pubcfg.json` (`vol`, `range_line`, `adhyaya_line` from `volN/STATUS.md`/`volcfg.json`, `imprint`, `year`, `press`, `note_style`, `english_md`, `kannada_md`, `supplied_md`, `out`): **no publisher, ISBN or rights** (those live only in `publish/release.json`), no front-matter assets (pages 1–4 of A2a are placeholders). Then `python3 publish/build_all.py N`. Keep the page count, the `[printfix] …` line, the check result, and a copy of the `<h1>`/`<h2>` headings of `publish/out/volN_full.html`.

**Step 2. Clean-up of the English text, dry run first.** `python3 tools/rv/cleanup_remarks.py N all` prints counts per kind. The patterns were fitted on Volume 1: print every remark that would be kept **in part** and read them all, and read 30 whole-line removals of each kind. If a kind removes content (a reference, a figure, a reading, a sentence of the translation), fix the pattern in the shared tool, never by a volume exception. Then `… all --write`. Every removal is a row of `volN/review/removed_remarks.tsv`; `[?]`, `[sic]`, `**NOTE**`, `**GLOSS**` stay; `[?]`/`[sic]` are listed in `volN/review/open_readings.tsv`.

**Step 3. Build again and compare the headings with Step 1.** They must be equal, except headings that came from removed notes and, after Step 3b, the preface and contents appearing. In Vol 1 a removed note was the marker by which the cleaner inserted whole chapters. Read the family's cleaner (`publish/vol*_clean.py`) for strings it searches in the text (`startswith(`, `in first`, `re.match`) and make sure none was removed; if one was, restore it and exempt it in the tool.

**Step 3b. Front pages, preface, contents, list of abbreviations (final specification, user, Nov 28 2026).**
*3b.1 The order, as data (A2a).* (1) two designed pages [placeholder], (2) king, then guru, (3) present king and guru on one page [placeholder], (4) thank-you page [placeholder], (5) our preface [placeholder], (6) the original's preface, (7) contents, (8) list of abbreviations, (9) Pūrva-pīṭhikā/Introduction if the volume has one, (10) the text, (11) closing-remarks page [placeholder, optional, **off**]. Make it **one shared file `publish/front_order.json`** read by **both** builder families (`on` per entry; a page is deleted by removing the entry or `"on": false`, inserted by adding an entry: a built-in name, or `{"type": "placeholder", "title": "…"}`). If the file is already on `main`, use it unchanged and only add what your volume needs. If not, you make it once, in the shared step (`publish/printfix.py` or a new `publish/frontorder.py`) as a step on the **finished HTML** (it recognises the sections the builders emit: cover, title page, copyright, king, guru, present day, contents, preface, text) so that one mechanism serves the old builders and `volbook.py`; never in a volume builder. The old cover, title page and copyright page stay in the file, switched **off**. A placeholder page carries only its title and "to be supplied". Pages 1–4 carry no page number, pages 5–9 lower-roman numbers of this book, and the arabic numbering starts at 1 on the first page of the text (state this default in the hand-over). Do not design the placeholder pages and do not alter the king's and guru's pages: the user is designing them.
*3b.2 Preface of the original (item 6).* Where it is: see the report (`preface`); in family A and C it is a section of the English file (headings like `Pīṭhike (Preface) …`, `ಪೀಠಿಕೆ — PĪṬHIKE …`), in family B only `frontmatter_en.json` (Vol 15). **Check that the family's cleaner lets it reach the print:** `clean9` in `publish/vol67_clean.py` (Vols 9, 10) discards everything before the first Sūkta, preface and contents with it; Vols 7 and 8 print the preface. Target: heading **"Preface"**, the original's name ("Pīṭhike") in the footer (rule 1), a line "by …" only if the preface does not carry its own signature, no remark of ours in the heading ("Kannada, printed pp. …", "Roman folios …", "(PDF 7–15 …)"), no page heading of the working file in the body. Fix such a cleaner in the shared code, not by a volume exception. A volume with **no preface** in any form: print nothing, say so in the hand-over, translate nothing (a translation would cost agent or API tokens: show an estimate and ask).
*3b.3 Contents (item 7, rule 7).* One table **No. | Contents | Page** (`printfix.contents_table`, as Vol 1): the original's own contents in English, the page column giving the pages **of this book** (links resolve). For a Ṛk volume: a heading row per Adhyāya; for each Sūkta a bold row (No. = Sūkta number, Contents = incipit in italic transliteration, Page = where it begins) and under it one row per topic (Contents = topic, Page = this book's page for the printed page cited, No. empty); a line with two topics becomes two rows. **Sources by family:** A: a section of the English file, if there is one (Vol 9: full list with bullets "topic — N"; Vol 10: only a summary table plus prose; Vols 7, 8 and others: none); B and C: `contents_en.json` made from the supplied text by `contents_parse` (Vols 15, 18, 21); for the others **there is no contents in English and making one costs agent or API tokens: do not make it, ask the user** (show the number of entries and an estimate). Working notes inside a contents section ("The table gives for each Sūkta its incipit…", "(The incipits are those printed…)", the paragraph about the original's own abbreviations page) describe the making and do not print. **Faults of the shared step to repair there:** (i) `printfix.contents_sections` finds a section only by "Table of Contents" with a capital C (Vol 10 says "Table of contents"): make it case-insensitive; (ii) it does not read the bulleted form of Vol 9: extend it; (iii) `build_vol45.py` and the other old builders still print their **own generated contents** (Adhyāya, Sūktas, nested Ṛk lists), and `printfix.toc_tables` turns it into a broken table (Vol 7: 4 rows and about 177 stray list items): switch the generated list **off** as `build_vol1.py` does (`toc = []`). **Questions for the user, not decisions for you:** a volume with no contents in the English: no contents page, or a table of Sūktas only (number, incipit, page of this book) generated from the headings? A contents given as prose (Vol 10): may it be put into the list form by hand, as a logged repair that adds nothing?
*3b.4 List of abbreviations (item 8).* Placed right after the contents. `volbook.references_list_html` already makes it (from the one list `rv/references.tsv`, only works whose forms stand before a reference number in the volume's English); the old builders print none. Move the function into the shared step so both families call it, unchanged; check that the forms in this volume's English match the list; no Kannada column.
*3b.5 Introduction (item 9).* Only Vols 1 and 5 have a Pūrva-pīṭhikā/Introduction; for the others the entry prints nothing. Confirm it in your count of headings.

**Step 4. Check and look.** `python3 publish/pdf_check.py N` must pass. Then look at pages **as images** (`pdftoppm`), never at text copied from a PDF (it scrambles Devanagari): **all the front pages in their order** (check that every contents link lands on the right page), the first 20 pages of text, one page of each kind of content (a sūkta opening, a Ṛk with Saṃhitā/Pada/bhāṣya, word meanings, Special Topics, a grammar section, a table), and 10 pages spread over the volume.

**Step 5. Things the shared rules meet in this volume. Look at each; report before changing a rule:**
1. **Bold (rule 10)** sets whole bold sentences and bold words inside sentences as plain text. In a Ṛk volume some bold may be meant (the Sanskrit word before each meaning, a label): count what was removed, look at such a page, show the user two pages if intended bold is lost.
2. **Kannada script in the English (rule 13).** Sample 30 places of the built HTML: what kinds, does the transliterated result read properly? (Counts differ enormously: 0 in family C, 1,791 in Vol 12.)
3. **English inside quotation bars (rule 12).** The bars may also hold the Saṃhitā, Pada and bhāṣya blocks; check that only English renderings of quotations disappear and no part of a Ṛk (the edition's "English translation", the meanings, the Gist) is lost.
4. **Page headings** in the body: none may remain; if `pdf_check` finds one, widen `printfix.page_headings`, not the cleaner.
5. **Headings.** Part and chapter headings print in two lines with the original's name in the footer (rule 1; `printfix.headings` covers `h1.part`/`h2.chapter` only); Sūkta headings keep their look. **Title levels (rule 17) exist only where the Kannada text has chapter lines** (Vol 1 Part I); do not invent them elsewhere. If the user wants the Maṇḍala – Sūkta – Ṛk – parts structure restyled, that is a new rule: ask.
6. **Front pages, preface, contents, abbreviations:** Step 3b.
7. **Tables** (rule 14) and **lists over a page turn** (rule 4): find one of each and look.
8. **Lines ending in dots.** `python3 tools/rv/join_pages.py prep N` lists them with the Kannada beside each. Count them by kind and leave out those inside the edition's own printed English ("Embedded English translation, as given in the source"), which the book does not print. **Do not start readers or the Batch API:** give the user the number of real places and an estimate (Vol 1: 269 places cost about 1.2M agent tokens) and wait. A spreadsheet of the places is made only if the user asks.
9. In family C: how many `**NOTE**` and `**GLOSS**` print (they are the editor's markers; the release gate will refuse them later, a review copy shows them).

**Step 6. Records.** `volN/review/repair_log.md` (what was removed by kind, how it was checked, what was restored), `volN/STATUS.md`, `PUBLICATION_TODO.md` (row of the volume, change log, "Last updated"); `publish/BUILD_STATUS.md` is written by `build_all.py`. A new lesson goes into `docs/LESSONS.md`. Commit and push to the session's branch after Steps 2, 3b and at the end. **Push to `main` only when the user says so.**

**Step 7. Hand over.** Send the PDF, show the content of `publish/front_order.json`, and say in a few lines: build number and page count; counts before and after for `[?]`, `[sic]`, "as printed", session words (from `pdf_check`); what was removed by kind; what you looked at; what is not right yet; the questions of Step 3b.3 and Step 5; the default for page numbers of Step 3b.1. Then wait for the user's review.

## How the user's comments are handled (the user's standing instruction)
A comment on a page is almost always meant **for all pages and all volumes**. So: (1) write it as a rule in `docs/REQUIREMENTS.md` A4; (2) build it into the shared step `publish/printfix.py` / `publish/style_footer.css` (or the shared text tool), never into the volume's builder unless the thing exists only there; (3) rebuild, run the check, look at the page as an image; (4) answer with the build number. Ask the user to quote "build NN, p. N" (the build number is in the footer). Several comments together are fixed in one rebuild.

## Do not
- Do not build or touch any other volume. The user reviews one volume at a time and stopped an all-volume run on Nov 26 2026.
- Do not start readers, agents for translation, or the Batch API without showing an estimate first; the token budget is tight. Building and checking are scripts and cost nothing.
- Do not correct Sanskrit, numbers or references by hand or from memory; do not type Devanagari or IAST; do not edit the Saṃhitā, Pada or bhāṣya lines (derived data).
- Do not remove `[?]`, `[sic]`, `**NOTE**` or `**GLOSS**`; do not reword the translation; do not hand the user long lists to review.
- Do not write a per-volume tool or stylesheet; do not design the pages that A2a marks as placeholders.
- Do not report a step as done that you did not run, or a commit you have not seen in `git log`.

## Stop and ask when
The report says unfinished or unclear; a removal kind cannot be told from content by its form; the headings differ after the clean-up and you cannot see why; a shared rule would lose something that looks intended; the check fails for a reason that needs a new rule; a change to the shared step would alter how another volume prints; something needs agent or API tokens.
