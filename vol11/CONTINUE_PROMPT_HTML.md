# Prompt for the Vol 11 session (paste into a new Claude Code session on this repo; Sonnet is enough)

You **re-translate Volume 11** of the Rigveda translation (repo `bhargaviupa/rik-translation`) from the user's machine-read text, by the **Batch API route**, exactly as Vols 17 and 18 were made. The old Vol 11 was read from page scans (718 printed pages, 2,602 `[?]` marks), so it is redone, not repaired. You do not translate yourself and you start no translator agents: windows go to the API as batches, scripts check and commit them. Read `CLAUDE.md`, then `vol11/STATUS.md`, then `vol18/STATUS.md` (the volume finished by this route, with what went wrong and how it was repaired) and the last entries of `docs/LESSONS.md` (41–62). Do not read other volumes.

**The old translation is kept, untouched, in `vol11/legacy/`.** It is not a source for the new text and nothing is copied from it. It is used once, at the end, as a second reading (see "After the last page").

## Start (once)
1. `git fetch origin main && git merge origin/main` on the branch this session was given (the tools of Vol 18 are on `main`). Add that branch's name to `"branches"` in `vol11/volcfg.json` (and set `"branch"`) once the file exists (step 3). Never force-push; no pull request; merge into `main` only when the user says so.
2. `pip install indic-transliteration rapidfuzz openpyxl anthropic`. The API key is the environment variable `RIK_API_KEY`; never print it.
3. **Scaffold** (Vol 11 has none yet; it was a scan-based legacy volume): `mkdir vol11/legacy && git mv vol11/Rigveda_Samhita_Vol11_English_Translation.{md,docx,pdf} vol11/Rigveda_Samhita_Vol11_Kannada_Text.{md,docx,pdf} vol11/legacy/` (rename the English/Kannada md to `…_scan.md` as Vol 13 did; `vol11/scans/`, `vol11/review/` and `publish/out/vol11_full.pdf` stay as they are). Then `python3 tools/rv/batch.py new 11 --mandala 1 --start-page 1 --source "vol11/html/rig_11.md@1-718"` (empty English and Kannada files, "Done through printed p. 0"), and make `vol11/volcfg.json` carry the conventions of Vols 17–18 (copy the keys from `vol18/volcfg.json`: `window` 6, `mandalas` [1], `note_style` "NOTE", `no_iast_blocks` ["bhashya"], `grammar` "sanskrit", `layout` "subheads"). **Do not set `printed_english_label`**: the English printed under a Ṛk keeps the heading `Printed English` (user, Nov 12 2026; the "(H. H. Wilson)" label is on hold). Fill `vol11/STATUS.md` from `docs/STATUS_TEMPLATE.md` (decision, scope, inputs). Commit, push.
4. Money: every `submit` and every `api_front.py` call spends from the user's API budget (Vol 18 cost $8.89 for 851 pages, about $0.01 a page; Vol 11 is estimated at $7–8). **Show the user the estimate that `plan` prints and wait for a yes before each `submit`.** Ask how much of the budget is left before the first one (the user reported about $38 on Nov 11 2026 before Vol 18 and Vol 13 were run; other sessions draw on the same budget).

## Prepare the text (once, before anything is sent)
The supplied text is not in the repo yet. Do what `vol18/STATUS.md` ("Source and inputs") describes:
1. Ask the user to upload the files (`rig_11_1.md`, …); put them in `vol11/html/`, merge them losslessly into `vol11/html/rig_11.md` with `tools/rv/merge_md.py`; pictures out to `vol11/html/figures/` (`[figure: …]` lines); converter footer lines removed; nothing else changed.
2. `python3 tools/rv/html_pages.py` on it: page range (the scan edition has printed pp. 1–718 after roman front matter), where printed p. 1 begins (insert `<!-- page 1 -->` there if the text has no marker, as in Vol 18), and the **missing page numbers** (list them in `STATUS.md`; the user decided on Nov 12 that missing page markers are not chased when the content is there). Record the front-matter line numbers (preface, contents, abbreviations, board, title pages) in `vol11/html/_layout.json`.
3. Set `source` in `volcfg.json` to the real page range; scope from the text itself (expected: Maṇḍala 1 Sūktas 137–157, the Second Adhyāya of the Second Aṣṭaka; say so if the text shows otherwise).
4. `python3 tools/rv/batch.py audit 11` passes; `python3 tools/rv/api_batch.py plan 11 --windows 5` (free) for the token count per page. Update `STATUS.md`, commit, push, and tell the user what the text looks like before any `submit`.

## Order of work
1. **The preface first** (it stands before printed p. 1, so no window covers it; skip if the volume has none): `python3 tools/rv/api_front.py 11 FIRST LAST preface` (line numbers from `vol11/html/_layout.json`; about $0.25). If it prints PROBLEMS, repair `vol11/work/preface/en.md` by hand and rebuild with `--rebuild`; then `python3 tools/rv/api_front.py 11 FIRST LAST preface --install`, `audit 11`, commit, push.
2. **The body in stages of about 40 windows** (about 240 pages, about $3 each; about 718 pages in all):
   - `python3 tools/rv/api_batch.py plan 11 --windows 40` (free) → tell the user → on yes `python3 tools/rv/api_batch.py submit 11`.
   - Wait in the background (one job, nothing else on the repo meanwhile): poll `python3 tools/rv/api_batch.py status 11` every 30 s until it says `ended`, then `python3 tools/rv/api_batch.py collect 11`. `collect` applies each answer, lets the scripts settle what they can (quotations, markers, references, remarks, unplaced blocks, duplicate headings, figure lines that repeat a verse block, a missing `## Maṇḍala M` heading; all logged, `**NOTE**` where a decision is needed), runs the gates and commits window after window in page order. **No retries are sent** (default).
   - If `collect` stops at a window (`STOP at …`): read `WIN/gate_failure.txt`. The gate "blocks under the label of another section" means the model counted the `[[bN]]` blocks one off (it happened in 6 of 136 windows of Vol 18): repair `WIN/en.md` so that every `[[bN]]` stands under the label of its own section (kn.md's label line above block N says which), check with `python3 tools/rv/batch.py done 11 WIN --dry-run`, run `collect 11` again. Other stops: repair `WIN/en.md` or `WIN/kn.md` by hand (`batch.py fix`; letters of the supplied text unchanged; never change what the print says to pass a gate). A window `done` already committed but whose verify step failed is marked done by `collect` on the next run once its pages are in the volume file. Only if a whole page was left untranslated, re-send that stage's failures on purpose with `collect 11 --retries 1` and say so. Set `RV_REBUILD=1` when rebuilding a window with `done --dry-run`, or the dry run drops sūkta headings the volume already has.
   - While `collect` runs do not commit, push or switch branches yourself: it commits and pushes every window. Afterwards: `audit 11`, **`python3 tools/rv/check_labels.py 11`** (must say 0 under the label of another section), update `vol11/STATUS.md` (page reached, cost of the stage from `vol11/parts/batch_costs.md`, windows that needed a hand repair, number of `**NOTE**` marks), commit, push, and report to the user in a few lines before planning the next stage.
3. **After each stage look at the text itself**, not only at the counts: print one complete Ṛk of the new pages and the first lines of the `vol11/review/notes.tsv` additions; check that no sūkta heading is missing in sequence. **After the first stage run a QA sample** (HANDBOOK §11.5): 12 general and 12 Special-Topics pages checked against the Kannada by three fresh Opus agents (read-only, not told what to expect; the page extracts in the scratchpad; four groups: numbers/references, names/terms/quotations, negations/attribution, omissions/additions; ERROR / MINOR), `review/qa_sample.md`; this is cheap and found in Vol 18 what 136 window gates did not.
4. **End of the volume** (the last printed page with its colophon and closing lines, nothing added): do the steps of "After the last page", update `STATUS.md` with the totals and stop. The rest of the finishing checklist (`docs/HANDBOOK.md` §11: accent report, QA sample, front matter, PDFs) is a separate job: do not start it without the user.

## After the last page (free, by script; no API)
1. `python3 tools/rv/batch.py rkheads 11 --dry-run` must say "nothing to change"; every sūkta's Ṛks numbered 1…n; `python3 tools/rv/kn_headings.py 11 --write`; `python3 tools/rv/check_labels.py 11` reports 0.
2. Scan the finished English file for Kannada prose shown as Devanagari inside Sanskrit blocks (lines with Dravidian vowel signs ॆ ॊ ऎ ऒ and Kannada word endings in sūkta-introduction bhāṣya blocks; Vol 18 had 19 such blocks, cleaned by a logged repair) and for the doubled daṇḍa `। (*…|*) ।` after quotations; list them in `STATUS.md`.
3. **Second reading from the old translation**: compare, per printed page, the numerals and references (book.chapter.verse, verse numbers, Pāṇini sūtra numbers) of `vol11/legacy/…_scan.md` with the new English. Put the result in `vol11/review/legacy_compare.tsv` (page, old, new). If `tools/rv/legacy_compare.py` exists (Vol 13's session may have written it) use it, otherwise write it as a shared script. Do not change the new text from it: the supplied text is the base. The list is for the user.

## Stop and tell the user when
- `audit 11` fails and you cannot see why, or `collect` stops twice at the same window;
- a stage costs more than twice its estimate;
- the scope in `vol11/STATUS.md` does not fit what the text shows (a sūkta number out of sequence, a missing page range);
- the usage limit is near: commit and push first; the next session resumes with this same prompt (`plan` continues after the last committed page).

## What the user decided for this edition (already in `volcfg.json` and `tools/rv/BRIEF.md`; do not change without asking)
No translator remarks in the English text, one mark `**NOTE**` with the question in `review/notes.tsv`; no Kannada script in the English text; every part of a Ṛk under its own sub-heading; the bhāṣya block in Devanagari only, followed by a Gist that covers most of it; transliteration everywhere else; Pratipadārtha one word per line; the English printed in the edition headed `Printed English` (no attribution); a grammar section, where the volume has one, rendered in Sanskrit; page markers kept, missing ones not chased when the content is there; publisher/ISBN/rights only in `publish/release.json`, never in the volume.
